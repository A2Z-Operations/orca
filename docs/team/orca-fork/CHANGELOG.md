# Orca fork changelog

One line per fork build, newest first. Build recipe: `scripts/orca-fork/rebuild.sh` in the BLOWzer repo; version rule: a prerelease of the next upstream patch.

- `1.4.256-blowzer.5` (fork PR `fix/headless-serve-plugin-service`, fixes #19, refs #2) — headless `orca serve` gets a plugin service: the plain-Node serve runtime (orcad, the default under `orca serve --supervise`) now constructs the `PluginService` after RPC start (`src/main/orcad/orcad-plugins.ts`) with the same store-backed consent/enablement writes as the desktop, the safety list, the catalogs and installer, the runtime delegate (`workspace.*`, `terminal.*`, `agent.*`, `accounts.read` + `accounts.*` events from the host's own accounts, hooks incl. `agent.launch.before`, storage/secrets/settings, notifications) and the plugin RPC binding, so `orca plugin list|install|update|uninstall|enable|disable|dev load|catalog …|logs|system on|off` answer on a headless host and trusted-worker plugins activate (the plugin worker host `plugin-host-entry.js` now ships beside `orcad-server.js`). Window-only contributions degrade instead of failing: panels/custom editors/status bar items/fonts are listed in `orca plugin logs <key>` as having no window on this host; `statusBar.update`, `appearance.*`, `shell.openExternal`, `files.saveAs` and `plugins.devInspect` keep their desktop-only answers. `pluginSystemEnabled` is honoured as on the desktop; no new setting. Not run headless: the plugin auto-updater and the bundled-plugin bootstrap (nothing bundled ships in the orcad bundle). Plugin secrets seal through the host's installed `SecretStore` instead of `electron.safeStorage` directly (the one Electron import left in the plugin host path); on orcad the seal's key sits beside the data, so `secrets.set` is refused naming that gap and `secrets.protection` answers `unavailable`, while `secrets.get`, `storage.*` and `settings.*` work; the desktop keeps its Linux basic_text refusal sentence verbatim. Desktop path unchanged (`bindDesktopPluginRpcServices` passes the Electron frame sinks into the now electron-free binder).

- `1.4.256-blowzer.4` (fork PR `fix/proxy-status-prunes-live-slots`, refs #2) — auth-proxy slot hygiene: `orca account auth-proxy --status` (and every other read of `accounts.claudeAuthProxyStatus`) is a pure read; slot pruning runs once on its own, shortly after a slot is minted or a PTY exits, and, before dropping a slot, reads the live PTYs' environments and keeps (binds, records) any slot a running shell still carries; a transcript-inferred pane row (a typed `claude --resume`) records the slot its shell minted at spawn. Fixes the Leader "Not logged in" cut-off of 2026-11-10.

- `1.4.256-blowzer.2` (fork PR `fix/updater-guard-after-255`, refs #2) — updater guard restored after the v1.4.255 merge (self-built apps never check for, download or install stock releases). Upstream moved `updater-setup.ts` into `updater/lifecycle/`; the merge kept upstream's copy without the fork's `updaterDisabledReason()` hunks, so `1.4.256-blowzer.1` offered "Update Available — Orca v1.4.256". The guard is back in `lifecycle/updater-setup.ts` (menu check, programmatic check, and the packaged configure path before the autoUpdater is touched) with a lifecycle test (`updater.disabled-build.test.ts`) that a disabled build never calls the autoUpdater and sends no status.

- v1.4.255 merge lessons — when upstream moves a file the fork patches, grep the old path's fork hunks (`git log -p <merge-base>..blowzer/fork-only -- <old path>`) against the new path before closing the merge; a clean three-way merge on the new path says nothing about hunks that lived on the old one.

- `1.4.256-blowzer.1` (fork PR `fork/merge-v1.4.255`, refs #2; carries `fix/stale-default-tests`, fixes #13) — fork rebased on upstream v1.4.255 (from the v1.4.243 release line). Upstream moved the plugin, Claude launch, account-service, runtime and settings modules into owner folders; the fork's lines follow them: the plugin accounts API (`accounts.read`, `accounts.*` events, `accounts.listClaudeAccounts`) now sits in upstream's capabilities/contributions/events/workers modules and rides upstream's per-event capability gate; the Claude settings panels live under `settings/accounts/claude/`; the structured launch returns upstream's account recipe while keeping pool/proxy/registry pinning; the headless usage poll flips the proxy flags on upstream's always-running poll timer instead of stopping it; the system-language reader carries upstream's pre-ready (uncached) read so startup-failure dialogs are localized. Release-only v1.4.243 changes (tests, scripts) are dropped in favour of v1.4.255.

- Next build (fork PR `fix/stale-default-tests`, fixes #13, refs #2) — build gates now run with no files set aside: `claude-account-service.test.ts` and `orcad-account-services.test.ts` read the account defaults (auto-switch on, pool on since `09c2a21b493`) from the shared default-settings source instead of literals, and the auth-proxy idle-stream test carries the loaded-machine tolerances from the C ladder.

- `1.4.244-blowzer.17` (fork PR #10 `fork/mover-hardening`, merge `67ce4bc4f70`; carries set-hooks from .16) — session mover / auth proxy hardening: a pane reattached after a restart keeps its proxy slot (persisted pane rows + the listener asks for its old port); durable `account-moves.log` (`orca account moves --log [--since <iso>]`); stay/wait reasons kept instead of `stay`; model flips recorded `strategy: proxy`; auth-proxy health (unknown slots, last error) in Settings and `--status`; `claudeModelPolicyCoversExplicit` (`model-policy --set covers-explicit=on|off`); `--status` for `auto-switch`, `session-mover`, `pool`; `orca account usage`; Settings recent-moves table with an Accounts usage strip.

- `1.4.244-blowzer.16` — `orca repo set-hooks --repo <sel> [--setup "<cmd>"] [--archive "<cmd>"] [--setup-policy ask|run-by-default|skip-by-default] [--clear-setup] [--clear-archive] [--json]` binds a repo's setup/archive hook scripts from a terminal; merges into the stored `hookSettings` through the existing `repo.update` RPC (`src/cli/handlers/repo-set-hooks.ts`).
